# NORDVALE: Product Images and Videos

## Folders
```
incoming/                       <- drop NEW images / videos here (named {slug}-{colour-slug}.jpg / .mp4)
public/assets/products/         <- generated by `npm run images` (do not edit by hand)
    {slug}-{colour}.webp        detail variant, 1080px wide
    {slug}-{colour}-card.webp   card variant, 540px wide, about 45KB or less
    {slug}-{colour}.mp4         optional hover video (copied from incoming/)
    manifest.json               sizes, 24px LQIP (base64), cache hashes, which videos exist
```

## Add or replace images / videos later
1. Put files in `incoming/`, named `{product-slug}-{colour-slug}.jpg` (or .png/.webp) and `.mp4` for videos.
   Slug = product slug, colour slug = colour name lowercased with hyphens, e.g. `campus-varsity-forest-green-cream.jpg`.
2. Run:
```bash
npm run images
```
3. Refresh the page. The script prints a table of all 64 expected files (matched / missing), lists duplicates, and lists files it could not match.

To read from other folders too: `INCOMING="incoming;C:/path/to/more" npm run images`.

## Video slot
If `{slug}-{colour}.mp4` exists it is listed in `manifest.json`. On desktop it plays on card hover (touch: when the card is mostly in view, max 2 at once), muted, with the card image as poster. In the detail view it shows only for colours that have one. No video means the card stays an image, with no error.

## Speed
Cards load with high priority, then all 64 card images are decoded in idle time and kept in memory, so tab and colour switches show images instantly. A service worker (`public/sw.js`, production only) caches product images after the first visit, and `public/_headers` / `vercel.json` set year-long cache headers (URLs are versioned with a hash).
